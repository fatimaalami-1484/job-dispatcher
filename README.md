# JobMesh

JobMesh یک سیستم توزیع‌شده برای مدیریت و اجرای Jobها روی Agentهای مختلف است. در این معماری، یک سرور مرکزی مسئول ایجاد و مدیریت Jobها است و Agentها وظیفه دریافت و اجرای Jobهای مربوط به خود را بر عهده دارند.

---

# معماری پروژه

پروژه بر اساس معماری **Central-Agent** طراحی شده است.

هر بخش مسئولیت مشخصی دارد:

- **Central Server**: ایجاد Job، مدیریت وضعیت Jobها و ارتباط با Agentها
- **Agents**: دریافت و اجرای Jobهای اختصاص داده‌شده
- **MongoDB**: ذخیره اطلاعات Jobها
- **NATS JetStream**: برقراری ارتباط پیام‌محور بین سرور و Agentها

جریان کلی سیستم به صورت زیر است:

1. کاربر یک Job ایجاد می‌کند.
2. اطلاعات Job در MongoDB ذخیره می‌شود.
3. Central Job را از طریق NATS برای Agent مربوطه ارسال می‌کند.
4. Agent Job را اجرا می‌کند.
5. نتیجه اجرا دوباره از طریق NATS به Central برمی‌گردد.
6. وضعیت Job در سیستم به‌روزرسانی می‌شود.

---

# چرا NATS JetStream؟

برای پیاده‌سازی ارتباط بین سرور مرکزی و Agentها چند Message Broker مختلف بررسی شد؛ از جمله **Redis**، **RabbitMQ**، **Apache Kafka** و **NATS**. هر کدام مزایا و کاربردهای خاص خودشان را دارند، اما برای نیازهای این پروژه NATS JetStream مناسب‌ترین گزینه بود.

### Apache Kafka

Kafka یک پلتفرم بسیار قدرتمند برای پردازش جریان‌های داده (Streaming) در مقیاس بزرگ است، اما برای این پروژه راه‌اندازی و نگهداری آن نسبتاً پیچیده بود و امکانات آن فراتر از نیازهای فعلی پروژه محسوب می‌شد.

### Redis

Redis اگرچه قابلیت Pub/Sub دارد، اما تمرکز اصلی آن یک پایگاه داده درون‌حافظه‌ای (In-Memory Database) است و برای مدیریت قابل‌اعتماد صف‌های Job با قابلیت‌های موردنیاز این پروژه، انتخاب اول نبود.

### RabbitMQ

RabbitMQ از نظر قابلیت‌های صف‌بندی بسیار نزدیک به نیازهای پروژه بود و یکی از گزینه‌های اصلی محسوب می‌شد.

### NATS

در نهایت NATS به دلیل سادگی راه‌اندازی، سرعت بالا و مهم‌تر از همه قابلیت **JetStream** انتخاب شد.

JetStream امکاناتی را فراهم می‌کند که برای سیستم مدیریت Job بسیار کاربردی هستند:

- نگهداری پیام‌ها تا زمان دریافت آن‌ها
- استفاده از Durable Consumerها
- جلوگیری از از دست رفتن Jobها در صورت قطع موقت Agentها
- مدیریت ساده‌تر جریان ارسال و دریافت پیام‌ها

به همین دلیل، NATS JetStream تعادل مناسبی بین سادگی، کارایی و قابلیت اطمینان برای معماری Central-Agent این پروژه فراهم می‌کند.

# سرویس‌های پیاده‌سازی‌شده

در حال حاضر سرویس‌های زیر پیاده‌سازی شده‌اند:

| Method | Endpoint | توضیح |
|--------|----------|-------|
| POST | `/jobs` | ایجاد یک Job جدید |
| GET | `/jobs/:id` | دریافت اطلاعات یک Job بر اساس شناسه |

---

# ساختار Job

هر Job شامل اطلاعات زیر است:

| فیلد | توضیح |
|------|-------|
| `id` | شناسه عددی یکتا |
| `createdAt` | زمان ایجاد |
| `finishedAt` | زمان پایان اجرا |
| `agentId` | شناسه Agent مقصد |
| `fileName` | فایل یا اسکریپت قابل اجرا |
| `timeout` | زمان Timeout |
| `status` | وضعیت فعلی Job |

---

# وضعیت‌های Job

هر Job می‌تواند یکی از وضعیت‌های زیر را داشته باشد:

| وضعیت | توضیح |
|--------|-------|
| `PENDING` | در انتظار اجرا |
| `RUNNING` | در حال اجرا |
| `COMPLETED` | با موفقیت پایان یافته |
| `FAILED` | با خطا پایان یافته |
| `TIMEOUT` | به علت پایان یافتن زمان مجاز متوقف شده |

---

# وضعیت فعلی پروژه

در نسخه فعلی پروژه امکانات زیر پیاده‌سازی شده‌اند:

- ایجاد Job
- دریافت اطلاعات Job بر اساس شناسه
- ذخیره اطلاعات در MongoDB
- استفاده از شناسه ترتیبی برای Jobها
- طراحی معماری مبتنی بر NATS JetStream برای ارتباط بین Central و Agentها
